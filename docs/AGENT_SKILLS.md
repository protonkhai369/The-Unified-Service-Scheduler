# AI agent toolkit

Every AI coding agent used on this project (Claude Code, Codex, Antigravity) gets the same
spec-driven workflow and the same curated skills. Shared project instructions are in `AGENTS.md`.

| Agent | Skills | OpenSpec commands | Project rules |
| --- | --- | --- | --- |
| Claude Code | `.claude/skills/` | `/opsx:*` in `.claude/commands/opsx/` | `CLAUDE.md` (imports `AGENTS.md`) |
| Codex | `.codex/skills/` | `/prompts:opsx-*` in `~/.codex/prompts/` (user level) | `AGENTS.md`, `.codex/rules/PROJECT.md` |
| Antigravity | `.agent/skills/` | `/opsx-*` in `.agent/workflows/` | `.agent/rules/PROJECT.md` |

`scripts/install-agent-skills.sh [target-dir] [claude,codex,antigravity]` reproduces this setup byte
for byte, here or in another project. Without a tool list it configures every agent whose folder
already exists.

## Why these

- **Web backend, Spring Boot 4 aware.** `spring-boot-testing` and `java-testcontainers` already cover
  Boot 4 / Testcontainers 2 changes (`@MockitoBean`, `RestTestClient`, renamed artifacts and
  packages), which matter because this project is on Boot 4.1.
- **PostgreSQL, not Supabase.** `postgresql-table-design` covers `EXCLUDE USING gist` (the
  double-booking guard used here) and flags missing foreign-key indexes.
- **Verification discipline.** The superpowers skills force evidence before "done", root cause before
  fixes, and red/green tests, which is what the assessment's "AI Engineering & Verification"
  criterion looks for.
- **A web client, designed rather than improvised.** `ui-ux-pro-max` (added on the user's request
  when a frontend was planned) searches local, curated data: styles, palettes, font pairings,
  WCAG-based UX rules and stack-specific guidance, for example React. It runs with Python's standard
  library only. It makes no network calls and starts no processes. It writes files only with
  `--persist`, into `design-system/<slug>/` under the given directory, and the slug is sanitised
  against path traversal. Its results are recommendations to judge, not rules: its first design
  system for this project proposed a display font meant for festivals.
- **Security review everywhere.** Claude Code has a built-in `/security-review`; Codex and
  Antigravity get the `security-review` skill, which never applies patches without human review.

## Considered and left out

- `security-review` for Claude Code: same name as the built-in `/security-review` and would shadow it.
- `github/awesome-copilot` `postgresql-code-review`: centred on JSONB/RLS, uses Copilot-only
  `${selection}` syntax.
- `obra/superpowers` `writing-plans` / `executing-plans`: overlap with the OpenSpec workflow.
- `anthropics/skills` `frontend-design` / `webapp-testing`: overlap with `ui-ux-pro-max`, which the
  user chose for the web client.

## Local changes to upstream content

- `systematic-debugging/SKILL.md`: `superpowers:test-driven-development` and
  `superpowers:verification-before-completion` renamed to the plain skill names (superpowers normally
  installs as a namespaced plugin).
- `systematic-debugging/`: upstream `CREATION-LOG.md` and `test-*.md` (the skill's own test
  scenarios) not copied.
- `ui-ux-pro-max/SKILL.md`: `${CLAUDE_PLUGIN_ROOT}/.claude/skills` replaced by each agent's own skills
  folder (`.claude/skills`, `.codex/skills`, `.agent/skills`). The variable exists only when the skill
  is installed as a Claude Code plugin; upstream's own CLI makes the same substitution.
- `ui-ux-pro-max/`: only what the search needs at run time is copied: `SKILL.md`, `references/`, the
  four runtime scripts and the CSV data. Upstream's maintainer tools (`validate_data.py`,
  `scripts/tests/`) and provenance JSON files (1.3 MB, read only by those tools) are not copied.

## Archived configuration

The agent folders previously held configuration copied from an unrelated project (StudyHub:
Android/Kotlin app with a Supabase backend): skills with no recorded source, the Android/Kotlin and
Supabase skills, StudyHub rules, Antigravity "Maestro" agents, and workflows that were broken
(`plan.md` called a non-existent `project-planner` agent) or superseded (OpenSpec 0.x workflows,
replaced by the OpenSpec 1.x `opsx-*` commands). Everything was moved, not deleted:

- `.claude/archive/skills/`
- `.codex/archive/skills/`, `.codex/archive/rules/`
- `.agent/archive/skills/`, `.agent/archive/agents/`, `.agent/archive/rules/`, `.agent/archive/workflows/`

Agents do not load `archive/` folders. To restore an item, move it back to its original folder.
